# 손님용 조회 전용 시간표 ST-22

```http
GET /api/v1/stores/{storeId}/timetable?date=2026-10-20
```

로그인·CSRF·Idempotency-Key 없이 조회한다. `date`는 필수 `YYYY-MM-DD`이며 한국 날짜(Asia/Seoul) 기준이다. 공통 성공 봉투의 `success.data`는 아래와 같다. 응답 헤더는 `Cache-Control: no-store`다.

```json
{
  "date": "2026-10-20",
  "timezone": "Asia/Seoul",
  "openingHours": {"closed": false, "opensAt": "09:00", "closesAt": "18:00"},
  "busyTimes": [
    {"startAt": "2026-10-20T10:00:00+09:00", "endAt": "2026-10-20T11:00:00+09:00"}
  ],
  "availableTimes": [
    {"startAt": "2026-10-20T14:00:00+09:00", "endAt": "2026-10-20T15:00:00+09:00"}
  ]
}
```

## 조회 기준

- `openingHours`는 해당 요일의 현재 영업시간이다. `opensAt`·`closesAt`은 `HH:mm`이다. 휴무이면 `closed=true`, 두 시간은 null, `availableTimes=[]`다. 휴무로 변경하기 전에 만들어진 확정 예약은 `busyTimes`에 유지한다.
- `busyTimes`는 해당 매장·한국 날짜에 겹치는 `CONFIRMED` 예약의 시간만 담는다. 취소·노쇼·완료·미확정 신청/제안은 제외한다. 날짜를 가로지르는 예약은 조회 날짜의 자정 경계로 잘라 반환한다.
- `availableTimes`는 현재 공개 상태 `AVAILABLE`, 시작 전, 활성 시술, 현재 영업시간 내의 슬롯만 담는다. 확정 예약에 겹치는 슬롯은 제외하며 고객 개인의 다른 일정은 이 공개 조회의 판단 대상이 아니다.
- 취소·노쇼 후 생기는 `DRAFT` 빈자리는 포함하지 않는다. 사장님이 발행하면 포함되고 철회·예약·만료·시술 비활성화 후에는 제외된다. 철회나 취소로 비어 보이는 구간을 자동으로 예약 가능 구간으로 만들지 않는다.
- 시간은 `+09:00`, 구간은 시작 포함·종료 제외다. 목록은 시간순이며 중복 시간 구간을 제거한다. 인접 슬롯을 임의로 합치거나 빈 구간을 생성하지 않는다. 결과가 없으면 `[]`다.
- 두 목록에 없는 영업시간은 **확인 필요**로 표시한다. 이 화면에는 시간 선택·예약 실행 기능을 연결하지 않는다.
- 고객 이름·고객 ID·예약 ID·슬롯 ID·연락처·가격은 반환하지 않는다. 사장님용 `TimetableResponse`를 재사용하지 않는다.

## 최신 상태와 읽기 전용 동작

매번 DB의 현재 커밋된 상태를 읽고 결과를 서버에 캐시하지 않는다. 기존 취소·노쇼·발행·철회 요청이 성공한 뒤 재조회하면 변경 결과를 반영한다. 조회는 읽기 전용 트랜잭션이며 `expire()`를 호출하지 않는다. 시간 경과는 조회 조건으로 판단하므로 조회 자체가 DB 상태·버전·예약·이벤트·알림을 만들거나 시간을 선점하지 않는다.

프런트는 표시 중 30초마다, 화면 복귀 및 수동 새로고침 때 재조회한다. 날짜/매장을 바꾼 뒤 늦게 도착한 이전 요청은 버린다. 두 목록의 여집합을 예약 가능으로 해석하지 않는다. 새로운 조회 결과가 이전 화면 값을 대체해야 취소·철회된 구간이 남지 않는다.

## 오류

| 상태 | 코드 | 의미 |
| --- | --- | --- |
| 400 | BAD_REQUEST / INVALID_DATE | date 누락·형식·범위 오류 |
| 404 | STORE_NOT_FOUND | 존재하지 않는 매장 |
| 409 | TIMETABLE_LIMIT_EXCEEDED | 일별 조회 대상 500개 초과. 결과를 조용히 자르지 않음 |

명시적으로 잘못된 Bearer 토큰을 보내면 기존 인증 필터가 401을 반환할 수 있다. 공개 조회에는 인증 헤더를 보낼 필요 없다.

## 변경 범위와 적용

DB SQL·환경변수 변경 없이 새 API·공개 GET 권한·Swagger 계약을 추가한다. 기존 예약 생성·즉시확정 정책·사장님 예약 취소 API·빈자리 발행 옵션은 변경하지 않는다. 새로운 기능은 앱 코드 배포 후 운영 Swagger에서 `ST-22` 또는 `getCustomerTimetable`로 확인한다. 프런트와 운영 앱 배포는 이번 구현에 포함하지 않는다.

권한·응답 스키마·개인정보 제외·no-store, 취소/노쇼 후 미발행→발행→철회 재조회, 휴무·빈 배열·한국 날짜·상태별 제외, 만료 슬롯 조회의 DB/이벤트 불변을 테스트한다.
